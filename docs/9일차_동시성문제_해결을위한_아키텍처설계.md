# 9일차: FastAPI와 Redis를 이용한 이벤트 기반 아키텍처(EDA) 설계

## 1. 개요 (무엇을 공부했나요?)
- **동시성 문제란?** 여러 명의 사용자가 동시에 똑같은 행동을 할 때, 데이터가 꼬이거나 중복 처리되는 문제입니다.
- **해결 방법:** FastAPI와 Redis를 활용하여 요청을 이벤트 단위로 쪼개고 순서대로 처리하는 이벤트 기반 아키텍처를 설계합니다.

---

## 2. 주요 개념 정리
- **Event (이벤트):** 시스템에서 일어난 중요한 사건입니다.
- **Redis (메시지 브로커):** 이벤트를 순서대로 모아두었다가 필요한 곳에 빠르게 전달해 주는 우체통 역할을 합니다.
- **FastAPI (백엔드 서버):** 사용자의 요청을 받아 이벤트를 발생시키고, Redis와 통신하여 작업을 처리합니다.

---

## 3. 우리 프로젝트에 적용하는 아키텍처 설계 흐름
1. **요청 받기:** 사용자가 웹사이트에서 어떤 행동을 합니다.
2. **이벤트 발행:** FastAPI가 Redis에 메시지를 보냅니다.
3. **비동기 처리:** Redis에 쌓인 메시지를 보고, 서버가 백그라운드에서 안전하게 데이터를 처리합니다.
4. **결과 반환:** 사용자는 기다림 없이 빠르게 응답을 받습니다.
